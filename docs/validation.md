# 验证范围

使用 Godot 4.6.stable.official.89cea1439。各项检查数量、失败列表、正式关卡解法、原生 Editor 截图和发布程序摘要写入 `evidence/validation_summary.json`，由实际测试日志汇总。

规则检查覆盖推动、不同距离的击退、提前停止、无连锁冲击、压板筛选、门的任一/全部条件、占门保持，以及完整撤销和重开。正式关卡按当前 campaign 清单逐关重放，不依赖固定数量或顺序。参数和重放检查包含默认继承、实例覆盖、类型变体、规则修订，以及旧证明失效。

工作区使用隔离路径检查新建、复制、从内存另存、草稿、发布、撤回、正式排序和外部修改冲突；失败写入检查实际文件补偿。绘制检查覆盖分层、合法叠放、框选复制和移动、连线、缩放平移、错误定位、导入导出与试关副本隔离。恢复检查另外覆盖含冲突的中间布局、失效类型和参数、不安全结构的隔离保留，以及待保存顺序。

`tools/test_native_editor.ps1` 使用工程副本和便携 Editor 设置启动真正的 Godot Editor。测试实际 Inspector 参数控件、编辑历史中的撤销重做和跨关同步，通过真实输入事件完成试关，再调用发布、排序、撤回，最后回放机关关卡。参数修复也检查撤销能还原无效原值。截图直接取自原生 Editor 视口，没有用独立游戏窗口替代。

场景流程测试实例化真实主场景，通过 `Input.parse_input_event` 检查开始、暂停、设置、通关、撤销、选关、工坊和试玩返回。固定 UI 夹具与正式关卡解法分开记录。底部 HUD 还检查 Z/R/Space/F11/M/Q 按键与按钮一致、暂停输入隔离、静音同步和重复进入时的信号连接；1280×720 与 960×640 的键帽位置均在对应按钮下方、画面以内。

正式清单的11关都通过实际主场景派发按键完成，再从通关菜单撤销并重开。1280×720 和 960×640 两种视口下检查固定地格比例与操作栏。进阶关检查镜头的中间位置、角色是否留在画面内，以及重开后恢复起始视野。验证使用独立工程与进度文件。

快速输入检查先复现20毫秒间隔的三次独立方向点按只执行一步，修复后执行三步。回归覆盖方向与出拳顺序、HUD同入口、有限积压、长按与抬键、暂停、撤销、重开、切关、返回转场、胜利和退出。人工注入事件先等待引擎派发，再检查执行结果，避免把尚未派发误记为输入完成。

教学行为检查在真实 BoardState 中搜索反事实路径。第5关禁止移动物件提前截停后，穷尽19601个可达状态未获胜。第7关禁止经历离板关门，仅剩初始状态且无法获胜。第8关禁止非终局交接，穷尽1950个状态未获胜。每次上限120000，均未触限。三关另行验证记录解、完整撤销和重开。进阶关检查有效解法、关键制动与供电依赖、回收目标物件、逐步撤销和无重复棋盘状态。

Windows release 使用官方 4.6 x86_64 模板导出，并实际启动导出的 exe，重放正式关卡、检查运行时工坊隔离和退出日志。摘要包含二进制大小和 SHA-256。草稿、Editor 插件、测试、文档与可编辑源不进入运行包；这些文件保留在源码工程。

资源检查验证尺寸、导入、透明度、音频解码与循环数值。已查看实际游戏和 Editor 截图，修正了试玩面板透出作者画布的问题。底部撤销与重开使用各自图标和悬停态，按钮下方保留像素字体键帽。
