# 实现约定

本作使用 Godot 4.6 GDScript。棋盘是离散规则，不使用刚体模拟搬运。每次输入先提交一条命令，规则层完成碰撞、位移、机关和胜利结算，再交给表现层插值播放。因此帧率、音效时长和窗口大小不改变解法。

## 谁维护什么

关卡 JSON 是初始布局的权威来源，物件定义 JSON 是类型与参数的来源。BoardState 只持有它们的运行时副本，独立维护占用、朝向、门状态和命令历史。BoardView 只画当前状态与过渡。编辑器维护自己的文档历史，试关创建新 BoardState，退出后保留原文档。

场景根节点负责菜单、游玩和编辑器的切换；ProfileStore 只负责进度与设置；AudioService 只维护事件到音频的映射。局部事件使用直接类型信号，没有额外全局事件总线。对象数量很小，完整快照撤销比差量回滚更容易校验，当前棋盘上限24×24，后续扩大规模再考虑差量。

## 内容与协作

新关卡用编辑器制作，不复制代码。物件类型使用稳定 ID；实例使用独立 ID，门引用实例 ID。贴图路径、音频事件和参数有独立入口，换美术不改变规则。关卡按文件存储，Git 能查看布局与参数差异。格式带版本，未知版本会明确报错，不猜测性修复。

JSON 中只允许基本值和整数坐标。地图的地板、墙、目标、实体分层，支持目标下有箱子、压板上有角色等合法叠放。编辑期的结构校验不宣称关卡可解；内置关卡附解法命令，用同一 BoardState 重放验证。

## 失败与生命周期

无效动作不计步。重开恢复关卡初始状态；撤销恢复完整棋盘和朝向。每个动作结束后统一结算压板，门被占用时保持打开，空出后再关闭。退出试玩不会保存试玩位置。文件写入先落临时文件再替换，进度保留上一份备份；错误需要反馈给用户。

## 验收边界

核心测试覆盖碰撞、两格/提前停止、无连锁冲击、门、撤销/重开、八关解法和坏数据。界面测试覆盖开始、选关、暂停、通关、编辑、导出/导入和立即测试返回，并检查不同窗口尺寸。自动解法能证明指定初始布局存在一条解法，不能证明难度或新手可理解性；这些仍需要实际试玩。
