# 原生关卡工作区

`LevelWorkspace` 是 `@tool RefCounted` 服务，文件在 `features/editor/services/level_workspace.gd`。它只处理内容文件，不依赖 EditorInterface、控件、场景树或编辑器 Undo。主屏负责选择文档、未保存提示和历史，绘制控件与 Inspector 负责修改文档。

工作区默认读取 `content/levels/campaign.json`，正式关在 `content/levels/`，草稿和通关记录分别在 `content/workshop/drafts/`、`content/workshop/proofs/`。`configure` 可传入这四个路径；测试全部使用 `.tools/workspace_tests/` 内的隔离目录。

## 使用顺序

先配置一次工作区，再通过 `list_levels` 建立关卡库。列表按正式清单顺序返回发布关，未发布草稿排在后面；草稿优先提供显示标题。`id` 是稳定引用，`title` 可以修改，既有正式文件名不会跟着标题变化。

选择关卡时调用 `load_level(id)`，拿到独立文档副本。它优先载入草稿，同时记录正式文件和草稿文件的磁盘哈希，包括“当前没有草稿”的情况。普通列表刷新不会把已记录的旧基线改成外部新版本。

`new_level` 创建并保存一个未完成草稿，默认有矩形地板、没有目标和物件，出生点为 `[-1,-1]`。`duplicate_level` 保存新草稿，生成新的关卡 ID 与实例 ID，重映射内部机关引用，清空解法和旧验证字段。

`save_draft` 使用共享 `LevelCodec.validate_draft`，允许缺少出生点、目标、地板或机关连线的制作中状态，仍拒绝字段错误、越界、非法参数和冲突。它不会写正式关或清单。

试关产生记录后，`save_proof` 会调用真实 `ReplayProof.verify` 重放检查；`load_proof` 返回最后保存的记录，是否仍适用于当前文档应再次验证。`valid=true` 字段或相同哈希本身不能冒充通关记录。

`publish` 要求严格 `LevelCodec.validate` 和实际获胜重放。成功后写入正式关及验证记录，把验证命令写入 `metadata.solution`；新关自动加入正式清单，然后移除对应草稿。仅有解法、验证字段变化不会让列表永久显示 modified。

`unpublish` 将一关移出正式清单，保留为草稿，再移除正式副本。已有较新草稿优先保留；验证记录不被删除。撤回后的关卡可再次通过严格发布。服务不会自动撤回其他关卡。

`save_order` 只接受完整、不重复的已发布 ID 集合。遗漏、草稿 ID 或未知 ID 都会拒绝；清单的其他字段保留。

## 外部修改

草稿保存和发布可传入载入时的源哈希。界面应保留当前文档载入时的哈希，不能在文档仍有未保存修改时，用一次关卡库刷新得到的新哈希替代它。未传显式哈希时，服务使用自己记录的载入基线。

发现外部新建、修改或删除时返回 ERR_BUSY，保留磁盘版本，并在 `last_errors` 给出中文路径提示。需要显式重新载入后再编辑；重新 configure 也意味着重新建立工作区基线。未载入的既有文件不能靠空 expected_hash 静默覆盖。

## 写入与恢复边界

内容先写同目录临时文件、flush 并关闭，再用 rename 替换单个目标。发布和撤回先准备全部临时文件及原文件备份；后续步骤失败会按相反顺序补偿恢复。若操作系统也拒绝恢复，原始字节仍保留在 `.bak`，错误中给出恢复路径。

这是单文件替换加多文件失败补偿，不是跨文件 ACID 事务，也不是断电恢复日志。哈希检查没有提供跨进程文件锁；其他进程仍可能在最终检查与 rename 之间修改文件。界面层的 Undo 也不等于这些文件写入的磁盘事务。

关卡 ID 使用 1–128 位英文字母、数字、下划线、连字符，不能使用 Windows 设备保留名。文件上限 8 MiB。未完成草稿的 `revision` 可能为空，因为 ReplayProof 不把尚不可玩的内容标为可验证规则修订。

## 验证

运行 `Godot --headless --path . --script res://tests/test_workspace.gd`。测试覆盖列表合并、草稿、复制、参数改动导致验证失效、正式排序、外部新建/修改/删除冲突、发布登记失败、撤回失败补偿，以及恢复被系统拒绝时保留备份。所有写入使用临时配置路径，测试最后核对真实八关清单哈希未改变。
